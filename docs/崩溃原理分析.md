## 结论

1. **同一个指令、同一个"除数为 0"，只有被除数变了** → 这是**一条固定的代码路径**，不是"对象太多撑爆池子"那类并发崩溃。
2. 因此 **MaxDebris / 粒子系统 / DelayKillFrames 的调优对这条崩溃无效**（那套是对"体积型崩溃"的）。
3. 崩溃与"改完 ini 要不要重打战役"无关：规则只影响数值，不影响存档结构。
4. 待查：读同一存档后 **35 秒内发生了什么**（第一枪打的是什么 / 场上有没有核电站、油井、油桶 / AI 是否来攻）——这是缩小范围的关键线索。

## ★ 崩溃根因已定位（2026/10/05 22:35，静态分析 game.exe）

### 崩溃函数 = 维修费用计算（虚函数，建筑/单位/步兵/飞机共 4 张虚表共用）

反汇编 0x6DAEC0：

```
X = this->vfunc[vtable+0xAC]()          ; 对象价值(造价)
A = this->[0xA0]                        ; 对象的 血量上限(Strength)
q = A / Rules[0x1334]                   ; ★ 整数除法，会截断成 0
result = max(1, (X / q) * Rules[0x1338]) ; ★ q=0 时这里 idiv 除零 → 崩溃
```

字段身份由 Rules 读取器（0x64A6xx~0x64A7A7）直接证实：

| 键名 | 字符串地址 | Rules 内偏移 |
|---|---|---|
| `RepairPercent` | 0x7F08DC | +0x1338（double） |
| **`RepairStep`** | **0x7F08D0** | **+0x1334（int）★ 除数就是它** |
| `IRepairStep` | 0x7F08C4 | +0x1340 |
| `RepairRate` / `URepairRate` / `IRepairRate` | 0x7F08B8 / 0x7F08AC / 0x7F08A0 | +0x1348 / +0x1350 / +0x1358 |

### 崩溃条件

`血量上限 / RepairStep == 0`，即 **血量上限 < RepairStep**。

- 原版：血量 125/300/1000，`RepairStep=8` → 商 ≥ 15，永远安全
- 5血模式：血量 5，`RepairStep=8` → **5 / 8 = 0** → 必崩
- 触发时机：任何需要算维修费的场合 —— 玩家点维修、AI 自动修受损建筑（IQ RepairSell）、维修厂修单位。
  所以遭遇战里 AI 一有受损建筑就崩（32 秒内足够），战役里没碰修复逻辑就能过关。

### 修复（2026/10/05 22:36 已应用）

| 键 | 原值 | 新值 | 理由 |
|---|---|---|---|
| `RepairStep` | 8 | **1** | `5 / 1 = 5` ≥ 1，不再截断成 0 |
| `IRepairStep` | 20 | **1** | 步兵维修同源逻辑，20 > 5 同样会崩 |

备份：`rules.ini.bak3`（本次修改前）
副作用：维修每 tick 回 1 血（原 8），一栋 5 血建筑约 5 个 tick ≈ 5 秒修满；**总维修费不变**（仍是造价的 15%，分 5 次付）。
想修得快可以用 `RepairStep=5`（5/5=1 同样安全，一 tick 修满）。

### 附带扫描结果

全 exe 里"拿 Rules 字段当整数除数"的位置共 10 处（+0xAB4、+0xB9C、+0xBBC、+0x1324、**+0x1334**、+0x13F4、+0x13F8、+0x144C、+0x1454、+0x1480）。本次崩溃是 +0x1334(RepairStep) 这一处；其余位置的被除数与血量无关，暂不动。

## 第二轮修复（2026/10/05 22:55）—— 崩溃 3（22:47:48，仍是 006DAEE7）

时间线证明 RepairStep=1 已生效：22:35:32 改完 → 22:46:18 启动 → 22:47:48 崩。
RepairStep=1 后 `商 = 血量 / 1 = 血量`，所以只剩"**血量 = 0**"会崩。

### 找到 7 个血量默认 0 的类型（在类型表里，但没有 Strength 键）

| 类型 | 原因 |
|---|---|
| `[DeathDummy]` | 有段落，但没有 Strength 键 |
| `APACHE` | 段落被 `;` 注释掉 |
| `NAWAST` `GARADR` `NAHPAD` `CAEURO01` `CAIRSFGL` | 段落完全不存在 |

### 修复内容

1. **rules.ini**：给上面 7 个类型全部补 `Strength=5`（备份 `rules.ini.bak4`）
2. **game.exe 二进制补丁**（根治）：把那次除法直接删掉
   - `0x6DAEDC`: `F7 B9 34 13 00 00` (`idiv dword ptr [ecx+0x1334]`) → `B8 05 00 00 00 90` (`mov eax,5` / `nop`)
   - 效果：商恒为 5，`0x6DAEE7` 的 `idiv esi` 永远不可能除零
   - 语义：维修费/次 = (造价/5) × RepairPercent(15%)，5 次修满 = 造价×15% ✓ 与规则注释完全一致
   - 备份 `game.exe.bak-hp5`（4,485,392 字节）
